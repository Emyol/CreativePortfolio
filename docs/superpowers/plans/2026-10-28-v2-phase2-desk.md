# v2 Phase 2: Desk and Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v1 scroll page with the desk: six tapes, the 3D player, the dot field, real routes per track, the paper J-card, one control grammar, and Events as the first finished device. The other sections show their v1 bodies inside the J-card until phase 3.

**Architecture:** A route-group layout `app/(tape)/layout.tsx` loads content once and renders the persistent client `Desk` (3D view, tapes, overlays, transport, J-card frame); each track route renders only its section into the J-card, so navigating between tracks never remounts the renderer. Navigation state is derived from the pathname (`lib/desk/location`), and every animation is a GSAP tween from current values, so input never waits. All DOM controls (tape links, player keys) sit over the canvas and are the source of truth for keyboard and screen readers.

**Tech Stack:** Next.js 16.4 App Router, React 19.3, TypeScript, three.js 0.186 via the existing shared stage (`lib/three/stage.ts`), GSAP 3.15 (`lib/motion/gsap`), CSS Modules, Zod, Vitest + Testing Library, Playwright on the GPU.

**Spec:** `docs/superpowers/specs/2026-10-28-v2-desk-design.md` (read it first; this plan argues from it). Feel reference: `.superpowers/brainstorm/815-1793074112/content/tape-3d-events.html` (prototype; port behaviour, not code style).

## Global Constraints

- Branching: create `v2` from `main` once; this phase is branch `feat/v2-desk` off `v2`, PR into `v2`. Never push `main`. No Claude attribution in commits or PRs.
- Before writing layout or routing code, read `node_modules/next/dist/docs/01-app/01-getting-started/03-layouts-and-pages.md`, `04-linking-and-navigating.md` and `03-api-reference/03-file-conventions/route-groups.md`.
- Content rules (CLAUDE.md): never invent content; sample text only in `lib/content/fixtures.ts`; no phone number; events are attended.
- Sound off by default (`lib/sound`); every sound on the same frame as its visual.
- `prefers-reduced-motion` works live (`useMotionTier()` from `lib/motion/MotionProvider`, tier `none`).
- three.js loads only through `getStage()`; one renderer; dispose views on unmount.
- Every GSAP setup inside `useGSAP` or `gsap.context`, reverted on unmount.
- Paper is cool white, two inks (near-black plus the track ink); Doto only on screens; dark only on real screens.
- Contrast 4.5:1 for all text on paper and on screens; touch targets at least 44 px.
- Nothing fixed may overlap a control or text.
- Timing (spec **Timing**): first insert of a visit about 2.2 s to readable content; later switches at most 1.2 s, readable by about 0.6 s; direct route load settles in 0.3 s.
- Spotify: nothing loads before a visitor presses play (unchanged `Mixtape`).

## Review Focus

1. **Rapid input during a transition** (three tapes clicked in 300 ms, Back pressed mid-insert): the desk must end on the last requested route with the 3D state matching it, never stuck. Test in Task 7.
2. **Direct load of a deep route then Esc** (`/events/<slug>` opened from a link): Esc goes to `/events`, a second Esc to `/`. Test in Task 10.
3. **Resize or zoom while a tape is in**: the corner view, tape links and key links stay over their 3D objects. Test in Task 8.
4. **No WebGL or a lost context**: the desk falls back to the sprite player and drawn tapes, and every DOM link still navigates. Test in Task 8.
5. **An empty track**: no tape, a blank key that does nothing, its route 404s, and ◀◀/▶▶ skip it. Tests in Tasks 1, 6 and 10.
